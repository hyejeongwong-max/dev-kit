# 测试验收

这个流程只检查和报告，不改代码。发现问题就列出来，问用户要不要转到 `/dev-bugfix` 逐个修。

## 流程

1. **读清单**：读 `docs/验收清单.md` 和 `docs/进度.md`。没有验收清单时，根据进度文档和代码里的页面先起草一份，请用户确认后保存。

2. **自动检查**：
   - `npm run build`
   - `npm test`（`package.json` 里有这个命令才跑）
   - `git status`：有未提交改动就提醒用户

3. **浏览器检查**（能用浏览器工具时亲自做，否则把清单给用户逐条勾）：
   - 验收清单逐条过
   - 每个页面都能打开，Console 没有红色报错
   - 有数据的功能：新增 → 刷新 → 还在
   - 窗口拉窄到手机宽度时，没有横向滚动条，内容不重叠
   - 没有数据时（空状态）显示正常，不白屏

4. **输出报告**：

```markdown
## 测试报告（YYYY-MM-DD）
- 构建：通过 / 失败
- 自动化测试：通过 x 条，失败 y 条（或"没有"）

### 通过
- …

### 不通过
| 问题 | 怎么复现 | 严重程度（必须修 / 建议修） |
| --- | --- | --- |

### 建议
- 建议补进验收清单的检查项
```

5. **建议补自动化测试**：功能已经有 5 个以上，或者某处反复出问题时，建议用户给核心数据逻辑加 Vitest 测试，并加一个 `npm test` 命令。用户同意后再加。
